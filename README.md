# 全国大学生数学建模竞赛团队项目

本项目用于三人团队共同管理比赛资料、Python / MATLAB 代码、LaTeX 论文和正式结果。目前仅建立框架，不包含比赛数据、模型结果或论文正文。

## 目录用途

| 目录 | 用途 |
| --- | --- |
| `00_赛题与附件/` | 赛题与官方附件；大型原文件放网盘，并记录获取位置 |
| `01_文献/` | 文献笔记、引用信息；参考论文原文可放网盘 |
| `02_数据/原始数据/` | 官方原始数据，禁止直接修改 |
| `02_数据/清洗数据/` | 清洗后可供建模使用的数据 |
| `02_数据/中间数据/` | 数据处理与模型计算过程中的中间数据 |
| `03_代码/第一问/` 至 `第四问/` | 各问的 Python、MATLAB 等求解代码；按实际题目使用 |
| `03_代码/公共函数/` | 多个问题共用的函数和工具 |
| `04_结果/第一问/` 至 `第四问/` | 各问正式数值结果、表格和结果说明 |
| `05_图片/第一问/` 至 `第四问/` | 各问输出的图表 |
| `06_论文/` | LaTeX 主文件、参考文献配置等论文源文件 |
| `06_论文/sections/` | 分章节论文源文件 |
| `06_论文/figures/` | 论文实际引用的定稿图片，与对应计算结果保持一致 |
| `07_提交文件/` | 经团队核对后的最终提交文件，包括需要提交的 PDF |

空目录用 `.gitkeep` 保留。目录有实际文件后可移除对应 `.gitkeep`。

## 推荐分工

- **建模手**：理解题意、提出假设、设计模型、分析合理性，与编程手核对公式和输出。
- **编程手**：数据清洗、Python / MATLAB 求解、验证计算、输出正式数据与图表。
- **写作手**：组织 LaTeX 论文、统一符号与图表、整理参考文献和提交文件。

三人都应参与检查。修改前在群里说明负责的文件；公共函数、主论文文件等共享文件同一时间指定一人修改。

## 比赛期间的协作

三人默认使用同一个 `main` 分支，不使用复杂分支流程。远程仓库首次准备好、其他成员克隆项目后，日常顺序为：

1. 开始工作先 `git pull`，获取队友更新。
2. 修改自己负责的文件，运行必要检查，把结果保存到项目中。
3. 完成一个小任务后执行 `git status`，检查改动；再执行 `git add .`、`git commit -m "说明本次完成的内容"`、`git push`。
4. 告知队友已更新哪些内容。详见 [GIT使用说明.md](GIT使用说明.md)。

原始数据禁止直接修改、覆盖或删除。清洗代码应读取 `02_数据/原始数据/`，将处理结果写入 `02_数据/清洗数据/`。

正式结果必须保存到项目目录，不能只存在某个人电脑上。小型、必要的结果纳入 Git；大型结果放在项目对应目录并同步网盘，在 Git 中另存说明，记录网盘位置、文件名、生成脚本及输入数据，确保队友可以获取和复现。上传大型文件前先确认是否适合纳入 Git。

## 文件命名规范

团队新建的代码、数据、图表和结果文件统一采用：

`日期_问题_内容_v版本_负责人.扩展名`

日期为四位月日（如 `0909`），问题写 `第一问`、`第二问` 等，共用文件可写 `公共`。版本从 `v01` 开始，依次为 `v02`、`v03`……负责人使用一致的姓名或团队约定标识。

示例（仅说明命名，不创建这些文件）：

- `0909_第一问_数据清洗_v01_张三.py`
- `0909_第一问_优化模型_v02_李四.py`
- `0910_第一问_结果图_v01_张三.png`

禁止使用 `最终版`、`最终版2`、`最新版`、`真的最终版`、`新建文档(1)` 等无法管理版本的文件名。Git 记录每次小修改；需要保留一个明确阶段版本时再递增文件名版本，并同步更新引用路径。

官方原文件保持原名；`README.md`、`.gitignore` 等固定用途文件保留标准名称。MATLAB 函数文件等有工具命名限制的文件使用合法名称（如 `fit_model.m`），在文件头注明日期、问题、版本和负责人。比赛要求的提交文件名以官方规范为准。

## 工具与资料管理

Python、MATLAB、LaTeX 的源文件应纳入 Git，依赖环境和编译缓存不提交。后续使用 Mrite / Codex 时，检查其生成文件，保留必要配置和可复现成果，排除临时内容；不要提交账号密钥。

网盘与 Git 的分工见 [网盘使用说明.md](网盘使用说明.md)。比赛规则和工具使用要求以当届官方规定为准。
